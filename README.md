# Compass

Лёгкий десктопный помощник трейдера: **акции МосБиржи** и **крипта** в одном приложении.
Графики, сигналы, бэктест, журнал сделок, AI-разбор. **Автоторговли нет** — приложение
не размещает ордера и не принимает торговых ключей.

> Не инвестиционная рекомендация. Сигналы — инструмент анализа, решение и риск за вами.

## Статус

Готово (этапы 0–3): данные МосБиржи и крипты, кэш свечей, три стратегии (пересечение
средних, RSI, пробой канала), бэктест, поиск сигналов по расписанию, риск-калькулятор,
Telegram-уведомления, журнал сделок и интерфейс: график со свечами, объёмом, SMA и
маркерами сигналов/своих сделок, избранное, лента сигналов, проверка стратегий с кривой
капитала, журнал, тёмная/светлая тема. AI объясняет сигналы, разбирает журнал и отвечает
на вопросы в режиме обучения (Cursor CLI, Claude API, Ollama). Следующий этап —
упаковка и установщик, см. [docs/PLAN.md](docs/PLAN.md).

## Как это работает

- **Первый запуск без счёта:** панель «С чего начать» открывает учебный график
  BTC/USDT, ведёт к проверке стратегии и объясняет ограничения. Её можно скрыть и
  снова открыть кнопкой сверху. Счёт, торговые ключи и подписка на котировки не нужны.
- **Живой график OKX:** публичный WebSocket обновляет текущую свечу выбранной
  спотовой пары. После обрыва приложение переподключается и загружает окно истории
  через REST. Над графиком видны источник, состояние связи, время получения и
  предупреждения о кэше/пропусках. Это время получения, а не измерение биржевой задержки.
  Сканер стратегий по-прежнему работает по расписанию с закрытыми свечами.

- **Сигнал** — смена позиции стратегии на последней *закрытой* свече (вход или выход).
  Незакрытая свеча игнорируется, повторный скан не дублирует сигналы.
  Для дневных свечей это значит: сигнал приходит после закрытия суток (полночь UTC у
  крипты, полночь МСК у акций), а не сразу после закрытия торгов.
- **Недоступный источник:** график продолжает показывать кэш с предупреждением.
  Сканер пропускает такой инструмент: новые сигналы и уведомления по нему не создаются,
  причина возвращается в ошибках ручного скана и учитывается в логе фонового.
  После успешного обновления поиск сигналов возобновляется.
- **Бэктест** — решение на закрытии свечи, сделка по открытию следующей, с комиссией и
  проскальзыванием. Только long, без плеча, все деньги в сделку, **без стоп-лоссов**.
  Хороший бэктест не гарантирует прибыль: он показывает, как правило работало на
  прошлых данных. На вкладке «Проверка» видны комиссия, проскальзывание и эти ограничения.
  Кнопка «Искать сигналы по этим настройкам» сохраняет стратегию и параметры для тикера:
  сканер и проверка истории используют одну и ту же связку. Без сохранения сканер
  проверяет все три стратегии с параметрами по умолчанию.
- **Журнал** — из сигнала «Сколько купить?» можно перейти к записи фактической сделки:
  количество, цена, плановый стоп, причина и заметка. Журнал выгружается в CSV. Приложение
  по-прежнему ничего не исполняет.
- **Стоп** в сигнале — ориентир «цена − 2·ATR(14)», нужен для расчёта размера позиции.
  В бэктесте он не участвует.
- **Размер позиции** считает код по формуле «потеря при стопе ≤ N% капитала» с учётом
  лота (акции) или шага количества (крипта).
- **Telegram:** `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в окружении; без них уведомления
  идут в лог (dry-run). Токен в логи не попадает.
- **AI:** по умолчанию выключен; провайдер и модель выбираются в настройках.
  Для Cursor CLI и Claude API требуется согласие на отправку данных. Для Claude
  можно задать `ANTHROPIC_API_KEY`; пакет `anthropic` входит в зависимости проекта.
  Cursor CLI и Ollama устанавливаются отдельно. AI получает рассчитанные приложением
  факты, а не исполняет сделки. При работе по кэшу предупреждение об актуальности
  передаётся модели и показывается вместе с ответом, в том числе повторным из кэша AI.

## API (http://127.0.0.1:8765/docs)

`/api/markets`, `/api/candles`, `/api/live` (SSE, параметры `symbol`, `tf`), `/api/watchlist`, `/api/strategies`, `/api/backtest`,
`/api/signals`, `/api/scan`, `/api/risk`, `/api/settings`, `/api/journal`.
AI: `/api/ai/status`, `/api/ai/providers`, `/api/ai/providers/{provider_id}/models`,
`/api/ai/explain-signal`, `/api/ai/review-journal`, `/api/ai/ask`.

## Запуск (разработка)

```bash
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -e ".[desktop,dev]"

# интерфейс (Node 22, pnpm): собирается прямо в src/compass/static
cd ui && pnpm install && pnpm build && cd ..

.venv\Scripts\python -m compass.desktop   # нативное окно (pywebview / WebView2)
.venv\Scripts\python -m compass           # только движок: http://127.0.0.1:8765
.venv\Scripts\python -m pytest            # тесты движка
cd ui && pnpm test                        # тесты интерфейса
```

Разработка интерфейса с горячей перезагрузкой: движок (`python -m compass`) на :8765 и
`cd ui && pnpm dev` (Vite на :5173 проксирует `/api` на движок).

Данные пользователя (кэш, вотчлист) — `%APPDATA%\Compass\compass.sqlite3`
(переопределяется `COMPASS_DATA_DIR`).
Кэш разделён по источникам и биржам. При обновлении схемы существующая база
сохраняется рядом как `compass.sqlite3.v<версия>.bak`. Старая криптоистория без
указания биржи сохраняется отдельно; новая загружается с выбранной площадки.

## Источники данных и ограничения

- **МосБиржа** — открытый ISS API. Бесплатные котировки идут с задержкой ~15 минут:
  для дней и недель неважно, для интрадея важно.
- **Крипта** — публичные данные через ccxt, ключи не нужны. Биржа по умолчанию — OKX
  (`COMPASS_CRYPTO_EXCHANGE`). На проверке из РФ Bybit отвечал 403, Binance — 451;
  если нужна такая площадка — задайте прокси в `COMPASS_PROXY`.
  Живой поток реализован для OKX (1m, 5m, 15m, 1h, 4h, 1d; сутки UTC), для остальных
  площадок остаётся периодический REST-опрос. Доступность зависит от сети; нулевая
  задержка не обещается. Подписки и ключи для публичного потока не требуются.
- **Бесплатный старт:** графики, индикаторы, бэктест и ручной журнал работают без AI.
  Журнал не является симулятором брокерского счёта. Облачный AI может требовать
  оплаты выбранного провайдера; он по умолчанию выключен.
