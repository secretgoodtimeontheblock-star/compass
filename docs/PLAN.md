# План и решения

## Архитектура

Один Python-процесс (FastAPI + SQLite) + веб-интерфейс в нативном окне (pywebview).
Рынки подключаются адаптерами (`markets/`): всё специфичное для рынка — внутри адаптера,
ядро видит только `Candle`. Акции и крипта — один движок, два адаптера.
Сервисы SQLite используют общую блокировку соединения на время чтения и транзакций,
включая commit/rollback; сетевые обращения не удерживают блокировку базы.

Позже: панель в ORION читает тот же локальный API (вне рамок этого репозитория).

## Принятые решения

- **Без автоторговли.** Кода размещения ордеров нет. Ключи, если появятся, — только
  read-only и только в Windows Credential Manager.
- **pywebview сначала, Tauri позже.** UI — обычная веб-страница, оболочку можно
  заменить перед упаковкой. Cargo/rustc на машине есть.
- **AI получает посчитанные данные и возвращает текст.** Цены, уровни, размер позиции
  считает код. Провайдеры: Cursor CLI (`--print --mode ask`, read-only), Claude API,
  Ollama, выкл.
- **Кэш:** докачка с последней свечи (она могла быть незакрытой — перезаписывается);
  источник упал — отдаём кэш с `stale=true`.
  Сканер пропускает такие данные до восстановления источника. AI получает предупреждение
  об актуальности данных; то же предупреждение возвращается в API вместе с ответом.
- **Стратегия инструмента:** пользователь сохраняет стратегию и параметры на вкладке
  «Проверка». Сканер этого тикера использует только их; без сохранения — все стратегии
  с параметрами по умолчанию. В результате бэктеста явно указаны комиссия, проскальзывание
  и ограничения модели.
- **Журнал:** из расчёта позиции по сигналу открывается запись сделки с причиной,
  плановым стопом и заметкой. Журнал экспортируется в CSV. Перед миграцией схемы
  база копируется в `compass.sqlite3.v<версия>.bak`.
- **Крипта:** OKX по умолчанию. Bybit/Binance с машины разработки недоступны (403/451) —
  прокси в настройках.

## Решения по итогам аудита (30.09.2026)

- **Стиль торговли — и дни/недели, и интрадей.** Основа остаётся на свечах 1h/4h/1d.
  Интрадей (1m/10m/15m) добавляется после пакетов A–D и только в границах OHLCV: стакан
  и bid/ask не восстановить, исполнение в бэктесте — по консервативному правилу; котировки
  ISS запаздывают ~15 минут, и интерфейс говорит об этом рядом с интрадей-графиком.
- **Валюта:** два счёта (рублёвый, USDT) без сложения; единого итога нет. Пересчёт по явному
  курсу — только если понадобится, с подписью курса и времени.
- **Распространение:** только для двоих. Подпись установщика и публичные условия данных не нужны;
  в README остаётся пометка «личное использование».
- **Бэктест: проверка вне выборки** строится на пакете B поверх принятого `validation.py`.
  Разбивка на окна — описательная; настоящая проверка (подбор на одном периоде, оценка на другом)
  ещё не сделана.

## Порядок пакетов

1. **J1. Защита локального API** (Host/Origin, токен сессии для окна) — выше остальных: чужая страница
   может писать в журнал. Готово, когда: атаки в тестах отбиты, мутация «убрать проверку» ломает тест,
   окно и `python -m compass` работают.
2. **A. Достоверность данных:** закрытость свечи везде (находка 2), контроль качества и покрытие,
   метаданные инструмента (лот/шаг цены/валюта, крипта — из биржи), тип ряда, выбор периода.
3. **C1. Бэктест 2-го поколения** + **B:** правила малой выборки, стопы/гэпы, размер по риску, настоящая
   проверка вне выборки, версия стратегии.
4. **D, E:** счета и лимиты; план как неизменяемый снимок, режим сделки, резервная копия журнала, импорт.
5. **F, H, G, I, J2:** сигналы (срок/статус), рабочее место, учебный счёт, AI-эталоны, CI и установщик.
Интрадей — после шага 3 при готовых A–C.

## Изменения контрактов (запись по правилу «ничего не ломать молча»)

- **Локальный API:** Host только локальный, Origin — свой; в окне приложения ещё и cookie сессии (`api/guard.py`).
  Внешние клиенты на `127.0.0.1` без токена продолжают работать в режиме `python -m compass`.
- **`/api/backtest`:** считает только по закрытым свечам; в ответе `warnings`, `data_quality`; при менее чем 10 закрытых сделках
  доля прибыльных, средняя сделка, профит-фактор, payoff, Sharpe, Sortino, Calmar, CAGR = `null`.
- **`/api/risk`:** учитывает комиссию и проскальзывание (по умолчанию 0.05%/0.05% для МосБиржи, 0.1%/0.05% для крипты),
  принимает `available`, `fee_pct`, `slippage_pct`; новые поля `risk_amount_worse`, `budget`, `warning`, `assumptions`.
  Количество стало меньше прежнего при тех же входных: расходы теперь входят в потерю при стопе.
- **БД, схема 7:** `signals.params` (JSON параметров стратегии). У прежних сигналов NULL, задним числом не заполняется;
  AI-объяснение таких сигналов берёт параметры по умолчанию и говорит об этом. Копия `.v6.bak` создаётся автоматически.
- **`GET /api/instrument`** (новый) и **`/api/risk`:** параметры инструмента читаются у биржи (`InstrumentInfo`): МосБиржа — лот, шаг цены,
  валюта, режим торгов, у облигаций номинал и НКД; OKX — шаг количества, шаг цены, минимальное количество/сумма. Цена облигации — % от
  номинала: стоимость покупки = цена·номинал/100 + НКД. Если параметры не получены, ответ говорит об этом (`complete=false`) и для крипты
  берёт шаг 1e-6 с предупреждением; лот МосБиржи без ISS берётся только из справочника. В ответ `/api/risk` добавлены `currency`, `warnings`.

- **Журнал, схема 8:** `journal.mode` (real/paper/historical; прежние записи — real), `journal.uid` (уникален), `journal.deleted_at`. Удаление стало
  мягким (`DELETE /api/journal/{id}` по-прежнему 204, запись можно вернуть: `POST /api/journal/{id}/restore`, список — `GET /api/journal/deleted`).
  `GET /api/journal` и `/api/journal/positions` по умолчанию отдают только реальные сделки (`mode=paper|historical|all`); позиции считаются по
  каждому режиму отдельно. Резервная копия — `GET /api/journal/backup.json`, восстановление — `POST /api/journal/restore` (по uid, без дублей,
  всё или ничего). AI-разбор журнала работает только по реальным сделкам. Копия `.v7.bak` создаётся при миграции.
- **Версия стратегии** (`strategies.strategy_version`): `правило/редакция/хэш параметров`. Хранится в сигнале (`signals.strategy_version`),
  в карточке бэктеста (`run_card.strategy_version`) и в плане. Правку логики правила сопровождает увеличение `Strategy.version`.
  У сигналов старого образца версии нет (NULL), задним числом она не вычисляется.
- **Планы сделок, схема 9:** таблица `plans` (неизменяемая: триггеры запрещают UPDATE и DELETE), `journal.plan_uid`. Новые маршруты:
  `POST /api/plans`, `GET /api/plans`, `GET /api/plans/{id}`, `GET /api/plans/{id}/review`. План хранит источник данных, версию стратегии,
  вход, стоп, цель, количество, расходы, расчётный и ухудшенный риск, причину; нулевое количество и пустая причина — отказ. Запись журнала
  может ссылаться на существующий план того же тикера. Сверка план/факт считает только записанные сделки: цена входа, количество, стоп,
  фактический риск против допустимого, результат и R. Резервная копия — формат версии 2 (с планами), копии версии 1 читаются.
  Копия `.v8.bak` создаётся при миграции.
- **Бэктест, движок версии 3** (`ENGINE_VERSION`): необязательные `stop_atr_mult`, `target_r`, `risk_pct` в `/api/backtest`. Без них — прежний режим
  (весь капитал, выход по сигналу). С ними: размер по риску тем же расчётом, что в калькуляторе (комиссии, проскальзывание, лот/шаг, свободные
  средства, номинал облигаций), стоп на N·ATR от закрытия сигнальной свечи, цель в R. Правила внутри свечи: открытие за стопом (гэп) — выход по
  открытию; стоп и цель в одной свече — принят стоп (порядок тиков не придумывается), свеча считается неоднозначной; после стопа/цели повторный
  вход только по новому сигналу; вход при открытии ниже стопа пропускается. Метрики добавлены: R, MAE/MFE, выходы по стопу/цели/гэпу,
  неоднозначные свечи, пропущенные входы. Сделка теперь несёт причину выхода, количество, стоп, цель, риск в деньгах. Карточка запуска
  перечисляет допущения исполнения. Результаты режимов между собой не сопоставимы: при размере по риску в рынке лишь часть капитала.
- **Бэктест, движок версии 3** (`ENGINE_VERSION="3"`): необязательные `stop_atr_mult`, `target_r`, `risk_pct` в `POST /api/backtest`
  (все пусты — прежний режим «весь капитал, выход по сигналу», результаты не изменились). Стоп = закрытие сигнальной свечи − N·ATR(14) (как в сканере);
  размер по риску — тот же расчёт, что в риск-калькуляторе (комиссии, проскальзывание, лот/шаг, свободные средства). Правила исполнения внутри
  свечи: открытие за стопом — выход по открытию (гэп); стоп и цель в одной свече — принят стоп; после выхода по стопу/цели повторный вход только
  по новому сигналу; вход пропускается, если открытие уже ниже стопа. В сделках новые поля (`exit_reason`, `qty`, `stop`, `target`,
  `risk_amount`, `pnl_amount`, `mae_pct`, `mfe_pct`, `bars`), в метриках — `avg_r`, `avg_win_pct`, `avg_loss_pct`, `avg_mae_pct`, `avg_mfe_pct`,
  `stops`, `targets`, `gap_exits`, `ambiguous_bars`, `skipped_entries`; при малой выборке (<10 сделок) статистика скрывается, как раньше.
  Доходность при разных размерах позиции несопоставима: сравнивать надо при одинаковом риске.
- **Проверка вне выборки** (`POST /api/validate`, модуль `oos.py`): история делится по времени (доля подбора 50–90%, не меньше 100 свечей на подбор и 50 на
  проверку); параметры перебираются (сетка до 300 сочетаний) и выбираются ТОЛЬКО на периоде подбора по «доходности к просадке» среди вариантов не менее
  чем с 10 сделками; выбранный вариант один раз оценивается на проверочном периоде, который торгуется отдельно (`backtest(..., start=k)`) с собственным
  капиталом. В ответе: разбиение, выбранный вариант, baseline без подбора, чувствительность к соседним значениям и к расходам (×1/×2/×3), вердикт
  (`held`/`degraded`/`inconclusive`, при <10 сделок на проверке — всегда `inconclusive`). Свойство «подбор не видит проверку» защищено тестом
  (замена цен второй части не меняет выбор и метрики подбора).
- **История проверок, схема 10** (`experiments`, только добавление, триггеры запрещают UPDATE/DELETE): каждый `POST /api/backtest` и `POST /api/validate`
  записывается (правило, версия, параметры, сетка, отпечаток данных, версия движка, итог). В ответах `trials` — сколько вариантов этого правила на этом
  инструменте пробовали ранее; от 20 вариантов — предупреждение о множественных проверках. `GET /api/experiments` — просмотр истории. Копия `.v9.bak`.
- **Счета и совокупный риск, схема 11** (`accounts`): у каждого рынка свой счёт со своей валютой и лимитами (капитал, риск на сделку, дневной лимит
  убытка, предел суммарного риска). Рублёвый счёт наследует капитал и риск из прежних настроек, капитал USDT-счёта НЕ придумывается (`NULL`,
  пока пользователь его не задаст). **Изменение поведения:** `/api/risk` и `/api/plans` берут капитал и риск из счёта рынка, а не из общей
  настройки `capital` (она осталась стартовым капиталом бэктеста); без капитала счёта — 422 с пояснением. Свободные средства =
  капитал + реализованный результат − стоимость открытых позиций (по журналу, только реальные сделки); учитывается по умолчанию как `available`.
  `POST /api/risk` возвращает `portfolio` (риск до/после, доля в позициях, дневной результат, корреляции с открытыми позициями) и добавляет
  предупреждения (превышение предела риска, дневной лимит, нехватка свободных средств, позиции без записанного стопа, корреляция ≥ 0.7 за ~150 дней;
  проверка по кэшу свечей). Всё — предупреждения, ничего не блокируется. Новое: `GET/PUT /api/accounts`, `GET /api/day` (панель дня по каждому счёту
  отдельно, без общего итога). Ограничения: без рыночных цен, нереализованный результат не учитывается; цена в журнале — деньги за единицу актива
  (для облигаций в рублях, не в % номинала). Копия `.v10.bak`.
- **Сигналы и наблюдение (пакет F), схема 12:** `signals.notified_at`, `signals.dismissed_at`, таблица `scan_state`. Статус сигнала вычисляется при
  чтении: `dismissed` (отклонён вручную, `POST /api/signals/{id}/dismiss|restore`) → `acted` (есть запись журнала или план по `signal_id`) →
  `expired` (позже `candle_ts + tf·(1 + signal_valid_bars)`) → `active`; в ответах `status` и `expires_at`, фильтр `GET /api/signals?status=`.
  Новые настройки: `signal_valid_bars` (по умолчанию 3), `quiet_hours` (`enabled`, `from`, `to`; окно может переходить через полночь; время местное),
  `paused_instruments`. В тихие часы сигналы сохраняются, внешние уведомления откладываются; после них накопившееся уходит одним дайджестом, устаревшее
  и отклонённое не рассылается. Старые сигналы при миграции помечены уже уведомлёнными (после обновления рассылки старья не будет). Сканер пишет
  состояние каждого инструмента (`ok/stale/error/short/paused`); `GET /api/watch` показывает его вместе с интервалом, временем последней и следующей
  проверки и явной пометкой, что наблюдение работает только при запущенном приложении; `GET /api/day` содержит `problem_sources`. Уведомление теперь
  уходит с сигналом из базы (с номером). Копия `.v11.bak`.
- **Учебный счёт и воспроизведение свечей (пакет G), схема 13** (`replay_sessions`, `replay_fills`): `POST /api/replay` замораживает копию закрытых свечей
  (до 5000, из них `replay_bars` ещё «закрыты» для пользователя), далее `GET /api/replay/{id}`, `/candles`, `POST .../order|stop|step|finish`,
  `DELETE .../order`. Клиент получает только открытые свечи — будущее не покидает сервер (тестом проверено по приметным ценам). Заявка
  исполняется по открытию следующей свечи с комиссией и проскальзыванием как в бэктесте; стоп — те же консервативные правила (гэп — по открытию).
  Учебные сделки хранятся в своих таблицах (неизменяемых триггерами) и НЕ попадают в журнал реальных сделок, панель дня, лимиты счетов и статистику.
  Итог сессии: капитал, доходность, «купил и держи» с начала, просадка, входы без стопа, максимальный риск на вход; доля прибыльных — только от
  10 закрытых сделок. Ограничения: пользователь видит даты и может помнить, что было; порядок внутри свечи неизвестен; ликвидность не учитывается.
  Копия `.v12.bak`.
